# 要求内容：入力まわりの UX 改善

> 作業ディレクトリ：`.steering/20261020-input-ux/` ／ 作成日：2026-10-20 ／ ステータス：承認済み
> 対象：パッケージ `com.mah.package-json-generator` v1.0.1 ／ 開発環境 Unity 6000.3.26f1（対応 Unity 6000.0 以上）
> 関連する永続的ドキュメント：`Docs/functional-design.md` §2.2（状態）・§2.3（データフロー）・§4（入力検証の冒頭の説明）・§5（ファイル入出力）・§6.2（レイアウト）・§7（非機能：永続化・エラー通知）・§8（K-12〜K-15 を修正済みにする。新しく見つけた問題を K-26・K-27 として追加）。いずれも更新要

## 1. 変更・追加する機能の説明

入力が検証に通らなかったときに、何も知らせずに直前の値へ戻している（K-12）。これを、欄のすぐ下にエラーを表示して知らせるようにする。
あわせて、次の 3 つを直す。
- Load に失敗したときに、入力中の内容をすべて消している（K-13）
- Create のときに、既存のファイルを確認なしで上書きしている（K-14）
- スクリプトの再コンパイルなどのドメインリロードで、入力内容が消える（K-15）

さらに、コードを読んで見つけた次の 2 つも、同じファイル操作まわりの問題なのであわせて直す。
- JSON の書き方が壊れた package.json を Load すると、例外で止まる（K-26）
- 存在しないフォルダを指定して Create すると、例外で止まる（K-27）

計画書の作業単位 #4。#10（読み込んだパッケージの記憶）は、ここで作る「入力状態をシリアライズする仕組み」を使う。

## 2. ユーザーストーリー

- パッケージの作者として、入力した値がなぜ受け付けられなかったのかを、その場で知りたい
- パッケージの作者として、Create や Load がうまくいったか、失敗したならなぜかを、Console を開かなくてもウィンドウで知りたい
- パッケージの作者として、フォルダの指定を間違えて Load しても、入力途中の内容を失いたくない
- パッケージの作者として、既存の package.json を誤って上書きしないように、上書きの前に確認してほしい
- スクリプトを編集しながらツールを使う開発者として、再コンパイルのたびに入力をやり直したくない

## 3. 受け入れ条件

**入力エラーの表示（K-12）**
- [ ] 次の欄に形式に合わない値を入力して確定すると、欄の下に赤いエラー（入力した値と、正しい形式の例）が表示される。値は今と同じく直前の値のまま
  - パッケージ名、著者の E-mail、著者の URL、変更ログ URL、ドキュメント URL、ライセンス URL、外部パッケージ名（行ごと）、サンプルのパス（行ごと）
- [ ] 同じ欄に正しい値を入力するか、空にすると、エラーの表示が消える
- [ ] Load に成功すると、すべての欄のエラー表示が消える

**操作結果の表示（K-12）**
- [ ] ファイル操作の欄（`Create package.json` / `Load package.json` のボタンの上）に、最後の操作の結果が表示される
  - Create 成功：作成したファイルのパス
  - Create 失敗：生成前チェックのエラー内容（今の `Debug.LogError` と同じ文言）
  - Load 成功：読み込んだファイルのパス。警告があった場合は、その件数と「詳しくは Console を参照」
  - Load 失敗：失敗の理由
- [ ] Console への出力（`Debug.LogError` / `Debug.LogWarning`）は今と同じく残す

**Load の失敗（K-13、K-26）**
- [ ] package.json が無いフォルダを指定して Load すると、エラーが表示され、入力中の内容はそのまま残る
- [ ] JSON として正しくない package.json（例 `{ "name": ` で途切れている）を Load すると、例外が出ずにエラーが表示され、入力中の内容はそのまま残る

**Create の上書き確認（K-14、K-27）**
- [ ] 指定したフォルダに package.json が既にあるとき、Create を押すと確認ダイアログが出る。「上書き」を選ぶと保存し、「キャンセル」を選ぶと保存しない
- [ ] package.json が無いときは、今と同じく確認なしで作成する
- [ ] 存在しないフォルダを指定して Create すると、例外が出ずにエラーが表示され、ファイルは作られない
- [ ] 書き込みに失敗したとき（読み取り専用のファイルなど）も、例外で止まらずにエラーが表示される

**ドメインリロード（K-15）**
- [ ] すべての項目を入力した状態でスクリプトを再コンパイルしても、入力内容・ライセンスの選択・フォルダーパス・Foldout の開閉・スクロール位置が残る
- [ ] ウィンドウを閉じて開き直したときは、今と同じく初期状態になる（閉じても残す機能は #10 で扱う）

## 4. 制約事項

- 編集するのは `src/PackageJsonGenerator/Assets/@MAH/PackageJson Generator/` だけ。作業の最後に配布フォルダへ同期する
- 既存の `.meta` の GUID を変えない
- JSON のモデル（`PackageJsonInfo`、`AuthorInfo`、`SampleInfo`）の出力内容を変えない（`[Serializable]` を付けても Newtonsoft の出力は変わらない）
- メッセージは日本語のまま（多言語化は #7 で行う）
- Unity 6000.0 に無い API を使わない。パッケージの依存を増やさない
- 識別子の綴りの誤りは直さない（#6）。`PackageJsonCreateWindow` の責務の分割はしない（#5）。ただし、今回の変更で増える処理は、#5 で分けやすいようにまとめて書く

## 5. スコープ外（今回やらないこと）

- ウィンドウを閉じても入力内容を残すこと、複数のパッケージの切り替え：#10 で行う
- 生成前チェックのエラーを、該当する欄の下にも表示すること（今回は操作結果の欄にまとめて表示する）
- 名前が正しくない外部パッケージの行など、Create 時の警告を欄ごとに表示すること
- 元に戻す（Undo）への対応
- 存在しないフォルダを自動で作ること
