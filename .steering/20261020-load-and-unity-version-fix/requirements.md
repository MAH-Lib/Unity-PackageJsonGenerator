# 要求内容：Load 時の例外と Unity バージョンの修正

> 作業ディレクトリ：`.steering/20261020-load-and-unity-version-fix/` ／ 作成日：2026-10-20 ／ ステータス：承認済み
> 対象：パッケージ `com.mah.package-json-generator` v1.0.1 ／ 開発環境 Unity 6000.3.26f1（対応 Unity 6000.0 以上）
> 関連する永続的ドキュメント：`Docs/functional-design.md` §2.1（`UnityVersion/` の構成）・§3.1（対応 Unity バージョンの初期値と変換）・§3.4（選択肢）・§8（K-4・K-5・K-6・K-7・K-17 を修正済みにする）。いずれも更新要

## 1. 変更・追加する機能の説明

`unity` や `version` が無い・形式が違う package.json を Load すると例外が出て読み込みが止まる問題（K-4、K-5、K-6）を直し、読めない値は初期値にして警告で知らせる。
対応 Unity バージョンの選択肢を、2026 年 10 月時点の最新版 Unity 6.6（`6000.6`）まで選べるようにする（K-17 ＋ 追加機能「Unity の最新バージョンまでの設定」）。一覧に無いバージョン（例 将来の `6000.7`）を Load した場合も、値を失わずに表示・出力できるようにする（K-7）。
計画書の作業単位 #3。Unity のバージョンは今後も増えるので、選択肢を「Major ごとの enum」から「1 か所のバージョン表」に変え、追加しやすくする。

## 2. ユーザーストーリー

- Unity 6.3 以降を対象にパッケージを作る作者として、`6000.3`〜`6000.6` を対応 Unity バージョンに選びたい
- 他のツールや手書きで作った package.json を読み込む利用者として、一部の項目が無かったり形式が違ったりしても、読み込みが止まらずに残りの項目を編集したい
- 新しい Unity 向けの package.json を読み込む利用者として、ツールの一覧がまだ対応していないバージョンでも、値が勝手に変わらないでほしい
- このツールの開発者として、新しい Unity が出たときに 1 か所の表に追加するだけで選べるようにしたい

## 3. 受け入れ条件

**選択肢（K-17）**
- [ ] Major に `6000`（Unity 6）、`2023`、`2022`、`2021`、`2020`、`2019`、`2018`、`2017`、`5` が並ぶ
- [ ] Major `6000` の Minor に `0`〜`6` が並ぶ
- [ ] Major `5` の Minor に `0`〜`6` が並ぶ（今は `5.0` が無い）
- [ ] その他の Major の Minor は今と同じ（2017〜2019：`1`〜`4`、2020〜2023：`1`〜`3`。`2023.3` は正式版が出ずに Unity 6 になったが、既存の選択肢を減らさないために残す）
- [ ] ウィンドウを開いた直後の初期値は `6000.0`（このツール自身の対応下限と同じ）
- [ ] Major を変えると、Minor はその Major の一覧の先頭（最も古いもの）になる

**一覧に無いバージョン（K-7）**
- [ ] `"unity": "6000.7"` のように一覧に無いバージョンを Load すると、Minor の選択肢に `7` が「一覧外」として追加・選択され、Console に警告が出る。そのまま Create すると `"unity": "6000.7"` が出力される
- [ ] `"unity": "2024.1"` のように一覧に無い Major を Load した場合も同じく、Major・Minor とも値を保ったまま表示・出力できる
- [ ] 一覧外の値から一覧の値に選び直すと、「一覧外」の選択肢は消える

**Load 時の例外（K-4、K-5、K-6）**
- [ ] 次の package.json を Load しても例外が出ず、他の項目は読み込まれる。どの場合も Console に、どの項目をどう扱ったかの警告が出る

| 項目 | package.json の値 | 読み込み結果 |
|---|---|---|
| `unity` | キーが無い / 空 | 初期値 `6000.0` |
| `unity` | `"6000"`（Minor が無い） | Major `6000`、Minor は一覧の先頭 `0` |
| `unity` | `"abc"`、`"6000.x"`（数値でない） | 初期値 `6000.0` |
| `version` | キーが無い / 空 | `0.0.0` |
| `version` | `"1.2"`（要素が足りない） | `1.2.0` |
| `version` | `"1.2.3.4"`（要素が多い） | `1.2.3` |
| `version` | `"1.2.3-preview.1"`（プレビュー版） | `1.2.3`（プレビュー部分は #8 で対応するまで読み捨てる） |
| `version` | `"a.b.c"`（数値でない） | `0.0.0` |

- [ ] 正しい値（例 `"unity": "2022.3"`、`"version": "1.2.3"`）では警告が出ない
- [ ] 外部パッケージのポップアップで、バージョンにプレビュー表記を含む登録済みパッケージ（例 `1.0.0-pre.3`）を選んでも例外が出ず、`1.0.0` が入る（同じ変換処理を使っているため、あわせて直す）

## 4. 制約事項

- 編集するのは `src/PackageJsonGenerator/Assets/@MAH/PackageJson Generator/` だけ。作業の最後に配布フォルダへ同期する
- 既存の `.meta` の GUID を変えない。ファイルを削除する場合は `.meta` も一緒に削除する
- 警告は今の作りに合わせて Console（`Debug.LogWarning`）に日本語で出す。画面上での通知は #4（K-12）で行う
- Unity 6000.0 に無い API を使わない。パッケージの依存を増やさない
- 識別子の綴りの誤りは直さない（#6）。`PackageJsonCreateWindow` の責務の分割はしない（#5）

## 5. スコープ外（今回やらないこと）

- プレビュー版のバージョン（`-preview.1` など）を入力・出力できるようにすること：#8 で行う。今回は読み捨てて警告を出すだけ
- 現在の Editor のバージョンを `unity` / `unityRelease` に入れるボタン、`unityRelease` の形式チェック：#12 で行う
- Load に失敗したときに入力を消さないこと（K-13）：#4 で行う
- Major・Minor を自由入力できるようにすること（一覧外の値は Load したときだけ扱う）
- 新しい Unity が出たときに選択肢を自動で増やすこと（開発者が表に追加する）
