# 要求内容：ウィンドウの責務分割

> 作業ディレクトリ：`.steering/20261021-window-refactor/` ／ 作成日：2026-10-21 ／ ステータス：承認済み
> 対象：パッケージ `com.mah.package-json-generator`（package.json 上は `com.github.mah.package-json-generator` 2.0.0） ／ 開発環境 Unity 6000.3.26f1
> 関連する永続的ドキュメント：`Docs/functional-design.md` §1.1（構成図）・§2.1（コンポーネント構成）・§2.2（状態）・§2.3（データフロー）・§8（K-20・K-22 を修正済みにする）、`CONTRIBUTING.md` §5（動作確認に自動テストを追加）。いずれも更新要

## 1. 変更・追加する機能の説明

`PackageJsonCreateWindow`（約 1,300 行）が、画面の描画・入力の検証・設定と JSON の変換・ファイル操作のすべてを抱えている（K-20）。これを役割ごとのクラスに分け、Window は「全体の配置」と「Create / Load の操作」だけを持つようにする。**利用者から見た振る舞いは変えない。**
あわせて、バージョン番号に負の値を入力できる問題（K-22）を直す。
分けた検証・変換のクラスには、EditMode の自動テストを付ける。テストは開発用プロジェクトだけに置き、パッケージには含めない。
計画書の作業単位 #5。#6（綴りの修正）、#7（言語切り替え）以降の作業は、分けたあとのクラスに対して行う。

## 2. ユーザーストーリー

- このツールの開発者として、修正のたびに 1,300 行のファイルを読まなくて済むように、役割ごとにファイルが分かれていてほしい
- このツールの開発者として、検証や変換を直したときに壊していないかをすぐ確かめられるように、自動テストがほしい
- パッケージの作者として、バージョンに負の数を入れて不正な package.json を作ってしまわないようにしてほしい

## 3. 受け入れ条件

**分割（K-20）**
- [ ] 入力の検証（パッケージ名・E-mail・URL・サンプルのパス・生成前チェック）が、Window ではなく専用のクラスにある
- [ ] 入力状態と `PackageJsonInfo` の相互変換（バージョン文字列の変換、`unity` の解析、依存パッケージの変換を含む）が、Window ではなく専用のクラスにあり、`Debug` や `EditorGUILayout` を使っていない（警告は戻り値で返す）
- [ ] 必須項目・任意項目（キーワード）・サンプル・外部パッケージの描画が、それぞれ Window の外のクラスにある
- [ ] `PackageJsonCreateWindow` には、Window の生成・`OnEnable`・`OnGUI` の全体の配置・ファイル操作の欄・Create / Load の処理・操作結果の表示だけが残る
- [ ] 同じ入力で、分割の前と後の出力 package.json が一致する
- [ ] 分割の前と後で、画面の見た目・入力エラーの表示・操作結果の表示・確認ダイアログ・Console の出力が変わらない
- [ ] ドメインリロードで入力内容と Foldout の開閉が残る（#4 の動きを保つ）

**負の値（K-22）**
- [ ] パッケージのバージョン（Major / Minor / Patch）と外部パッケージのバージョンに負の数を入力すると、0 になる

**自動テスト**
- [ ] Unity の Test Runner（Window > General > Test Runner）の EditMode に、このツールのテストが表示され、すべて成功する
- [ ] テストは開発用プロジェクトのパッケージ外のフォルダにあり、配布フォルダ `PackageJsonGenerator/` には含まれない
- [ ] テストの対象：パッケージ名・E-mail・URL の検証、サンプルのパスの変換、生成前チェック（重複を含む）、バージョン文字列の変換、`unity` の解析、入力状態 → JSON → 入力状態の往復

## 4. 制約事項

- 編集するのは `src/PackageJsonGenerator/Assets/@MAH/PackageJson Generator/` だけ（テストは同じ開発用プロジェクトのパッケージ外 `Assets/@MAH/Tests/` に置く）。作業の最後に配布フォルダへ同期する
- 既存の `.meta` の GUID を変えない。新しいファイルには新しい GUID の `.meta` を付ける
- `PackageJsonCreateWindow` のクラス名・名前空間・メニューのパスは変えない（利用者のレイアウト保存や参照を壊さないため）
- 識別子の綴りの誤り（`PacckageName` など）は、移すときもそのままにする（#6 で直す）
- 画面の文字列は日本語のまま（#7 で多言語化する）
- パッケージの依存を増やさない（テストの `com.unity.test-framework` は開発用プロジェクトに既に入っているもので、パッケージの依存には加えない）
- Unity 6000.0 に無い API を使わない

## 5. スコープ外（今回やらないこと）

- 画面の文字列の多言語化：#7 で行う
- 画面のレイアウトやデザインの変更
- Window 自体（IMGUI の描画）の自動テスト
- `package.json` の `name`・`unity`・`version` の食い違い（前回のコミット `b066e79`）の整理
